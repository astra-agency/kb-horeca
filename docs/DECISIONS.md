## [2026-06-04] ADR-001: Astro + Starlight как основа KB

**Решение:** Использовать существующий проект Astro 6.4.4 + Starlight 0.39.3.

**Альтернативы:** Notion, Confluence, GitBook, MkDocs, Docusaurus.

**Обоснование:** Проект уже инициализирован. Starlight — лучший вариант для статической документации: fast, SEO, поиск из коробки, sidebar-навигация, MDX.

## [2026-06-04] ADR-002: Деплой на GitHub Pages

**Решение:** GitHub Pages через GitHub Actions (`.github/workflows/deploy.yml`).

**Альтернативы:** Netlify, Vercel, Cloudflare Pages.

**Обоснование:** Бесплатно. Репозиторий уже на GitHub. Zero config для статики.

**Требование:** `base: '/kb-horeca'` в `astro.config.mjs` — обязательно для subdirectory deploy.

## [2026-06-04] ADR-003: Сохранить оригинальный английский контент

**Решение:** Оригинальные разделы Operations / Compliance & Safety / Reference оставить без изменений.

**Альтернативы:** Удалить, перевести.

## [2026-06-04] ADR-004: Структура sidebar — slug без /index

**Решение:** В Starlight sidebar для `index.md` использовать slug папки (`hotels`), а не `hotels/index`.

**Альтернативы:** `hotels/index`.

**Обоснование:** Starlight резолвит `index.md` → slug папки. Использование `hotels/index` вызывает ошибку сборки: `"The slug 'hotels/index' specified in the Starlight sidebar config does not exist"`.

**Обоснование:** Целевая аудитория — российский HoReCa рынок.

## [2026-06-04] ADR-006: Stub-страницы для недоступных сайтов

**Решение:** Для сервисов с недоступными сайтами (kontur.ru/hotel 403, logus.ru ECONNREFUSED, saby.ru/hotel 404) — создавать stub с известными данными, обогащать через поиск.

**Обоснование:** Лучше иметь базовую страницу с корректными данными, чем пустое место в навигации.

## [2026-06-04] ADR-008: Абсолютные пути в ссылках между страницами

**Решение:** Все внутренние ссылки — абсолютные с префиксом `/kb-horeca/`, без `.md`, с завершающим `/`.

**Альтернативы:** Относительные пути (`./delivery.md`), пути без base (`/restaurants/delivery/`).

**Обоснование:** Starlight не резолвит `.md` расширения в ссылках → 404 в браузере. Относительные пути без расширения (`./delivery/`) работают, но абсолютные надёжнее при рефакторинге структуры. Путь без `/kb-horeca/` base-prefix не работает при деплое на GitHub Pages subdirectory.

**Формат:** `/kb-horeca/<раздел>/<slug>/`

## [2026-06-05] ADR-009: YAML frontmatter — кавычки для значений с `: `

**Решение:** Любое поле `title:` или `description:` содержащее `: ` (двоеточие + пробел) ОБЯЗАТЕЛЬНО оборачивать в двойные кавычки.

**Проблема:** YAML трактует `: ` как разделитель маппинга. Без кавычек — `bad indentation of a mapping entry` при сборке.

**Неправильно:** `title: Гостевой цикл: от бронирования до повторного визита`
**Правильно:** `title: "Гостевой цикл: от бронирования до повторного визита"`

**Затронутые файлы:** 11 файлов исправлено в сессии 4 (все с `: ` в заголовках).

## [2026-06-05] ADR-010: Структура раздела «Кейсы»

**Решение:** Кейсы хранятся в `src/content/docs/cases/`, каждый кейс — отдельный файл. Структура: frontmatter → Контекст → Задача → Что было сделано → Результат → Что важно учесть → Связанные материалы.

**Альтернативы:** Встроить в существующие статьи; создать отдельный раздел в sidebar без подгрупп.

**Обоснование:** Кейсы — самостоятельный тип контента. Перелинковка кейс ↔ статья создаёт навигационную сеть без дублирования.

**Ссылки в кейсах:** `/kb-horeca/<path>/` — тот же абсолютный формат что ADR-008.

## [2026-06-05] ADR-011: Sidebar — нетехнический контент в Отелях/Ресторанах, IT в Сервисах

**Решение:** Разделы «Отели» и «Рестораны» в sidebar содержат только нетехнический контент (управление, персонал, гостевой опыт, операции). Всё IT (PMS, POS, Channel Manager и т.д.) перемещено в раздел «Сервисы».

**Обоснование:** Целевая аудитория — управляющие и владельцы. Нетехнический контент (как работать с персоналом, как отвечать на отзывы) и IT-инструменты — разные задачи. Разделение снижает когнитивную нагрузку навигации.
