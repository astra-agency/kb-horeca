## [2026-06-04] ADR-001: Astro + Starlight как основа KB

**Решение:** Использовать существующий проект Astro 6.4.4 + Starlight 0.39.3.

**Альтернативы:** Notion, Confluence, GitBook, MkDocs, Docusaurus.

**Обоснование:** Проект уже инициализирован. Starlight — лучший вариант для статической документации: fast, SEO, поиск из коробки, sidebar-навигация, MDX.

## [2026-06-04] ADR-002: Деплой на GitHub Pages

**Решение:** GitHub Pages через GitHub Actions (`.github/workflows/deploy.yml`).

**Альтернативы:** Netlify, Vercel, Cloudflare Pages.

**Обоснование:** Бесплатно. Репозиторий уже на GitHub. Zero config для статики.

**Требование:** При subdirectory deploy нужен `base: '/kb-horeca'`. После перехода на собственный домен (`kb-horeca.site`) `base` убран — сайт на корне.

## [2026-06-04] ADR-003: Сохранить оригинальный английский контент

**Альтернативы:** Удалить, перевести.

## [2026-06-04] ADR-004: Структура sidebar — slug без /index

**Решение:** В Starlight sidebar для `index.md` использовать slug папки (`hotels`), а не `hotels/index`.

**Альтернативы:** `hotels/index`.

**Обоснование:** Starlight резолвит `index.md` → slug папки. Использование `hotels/index` вызывает ошибку сборки: `"The slug 'hotels/index' specified in the Starlight sidebar config does not exist"`.

## [2026-06-04] ADR-005: Язык контента — ru-RU

**Решение:** Основной контент на русском. Конфиг: `defaultLocale: 'root'`, `lang: 'ru'`.

**Обоснование:** Целевая аудитория — российский HoReCa рынок. EN — дополнительная локаль.

## [2026-06-04] ADR-006: Stub-страницы для недоступных сайтов

**Решение:** Для сервисов с недоступными сайтами — создавать stub с известными данными, обогащать через поиск.

**Обоснование:** Лучше иметь базовую страницу с корректными данными, чем пустое место в навигации.

## [2026-06-04] ADR-008: Абсолютные пути в ссылках между страницами

**Решение:** Все внутренние ссылки — абсолютные, без `.md`, с завершающим `/`.

**Альтернативы:** Относительные пути (`./delivery.md`), пути с base-prefix.

**Обоснование:** Starlight не резолвит `.md` расширения → 404 в браузере.

**Формат (текущий, домен kb-horeca.site):** `/<раздел>/<slug>/`

**Формат EN:** `/en/<раздел>/<slug>/`

## [2026-06-05] ADR-009: YAML frontmatter — кавычки для значений с `: `

**Решение:** Любое поле `title:` или `description:` содержащее `: ` ОБЯЗАТЕЛЬНО оборачивать в двойные кавычки.

**Неправильно:** `title: Гостевой цикл: от бронирования до повторного визита`
**Правильно:** `title: "Гостевой цикл: от бронирования до повторного визита"`

## [2026-06-07] ADR-014: Starlight i18n — root locale для RU, EN в /en/

**Решение:** `defaultLocale: 'root'` с `lang: 'ru'`. EN контент в `src/content/docs/en/`.

**Альтернативы:** Раздельные папки `ru/` и `en/`, отдельный сайт для EN.

**Обоснование:** Starlight root locale — стандартный паттерн когда основной язык без префикса. RU контент остаётся в `src/content/docs/` без изменений. EN добавляется в `src/content/docs/en/` без переструктурирования.

**Следствие:** Sidebar slugs локаль-агностичны — `hotels/revenue/revpar-adr-occupancy` резолвится в RU-файл для root locale и EN-файл для EN locale автоматически.

## [2026-06-07] ADR-015: EN-only кейсы — RU стабы в root locale

**Решение:** Для 7 кейсов, существующих только в EN (`cases/inventory-management` и др.), создать минимальные RU-стабы с редиректом на EN-версию.

**Альтернативы:** Убрать из sidebar, создать отдельный EN-only sidebar раздел.

**Обоснование:** Starlight sidebar ищет slug в обоих локалях при сборке. Отсутствие root locale файла → ошибка `slug does not exist`. Стабы — минимальный fix без переработки sidebar.
